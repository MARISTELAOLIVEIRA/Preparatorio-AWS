EC1 · estudo de caso

Seis tipos de dado, seis gavetas

As máquinas da Ingresso Candango já rodam (aula 6). Agora é decidir onde guardar cada coisa:

  1. O sistema e os programas do servidor do site.
  2. As fotos dos shows e os PDFs dos ingressos: milhões de arquivos, abertos pela internet.
  3. Uma pasta compartilhada que várias máquinas Linux do site leem e gravam ao mesmo tempo.
  4. Os ingressos de shows antigos, que o contador mandou guardar por cinco anos e quase ninguém abre.
  5. Arquivos temporários de um processamento, que podem sumir sem problema.
  6. Os backups da salinha do escritório, que a equipe quer mandar para a nuvem como se fosse um disco local.

Para pensar

  1. Faz sentido pagar o mesmo preço para guardar um ingresso de cinco anos atrás e a foto do show de hoje?
  2. Um disco pode ficar ligado a várias máquinas ao mesmo tempo?
  3. O que acontece com os arquivos temporários quando a máquina é desligada?

C1–C4 · conceitos

Cada dado na gaveta certa

C1

Bloco, arquivo e objeto

São três jeitos de guardar dados, e cada serviço da AWS é um deles.

TipoComo funcionaNo dia a diaNa AWS
BlocoUm disco ligado a uma máquina. O sistema operacional formata e usa.O SSD do seu notebook.Amazon EBS
ArquivoPastas e arquivos compartilhados pela rede, por várias máquinas.A pasta da rede do laboratório.Amazon EFS e Amazon FSx
ObjetoCada arquivo vira um objeto com nome, dados e etiquetas, guardado num "balde" e aberto por um endereço.Um armário de caixas etiquetadas, cada uma com o seu endereço.Amazon S3

Como é no Azure: o S3 é o Armazenamento de Blobs, o EBS são os Discos Gerenciados e o EFS é o Arquivos do Azure.

C2

O Amazon S3 e as classes de armazenamento

No Amazon S3, você cria buckets (baldes) numa região e guarda objetos dentro deles. O nome do bucket é único no mundo inteiro. O S3 é projetado para 99,999999999% de durabilidade, os famosos "11 noves". Cada classe troca preço por velocidade de acesso:

ClasseParaAcessoZonas
S3 StandardDados usados o tempo todo.milissegundos3 ou mais
S3 Intelligent-TieringQuando você não sabe com que frequência vai usar: ele muda a classe sozinho.milissegundos3 ou mais
S3 Express One ZoneOs dados mais usados, com a resposta mais rápida.poucos milissegundos1
S3 Standard-IAPouco usados, mas que precisam abrir rápido.milissegundos3 ou mais
S3 One Zone-IAPouco usados e que dá para recriar, se a zona falhar.milissegundos1
S3 Glacier Instant RetrievalArquivo morto que precisa abrir na hora.milissegundos3 ou mais
S3 Glacier Flexible RetrievalBackup e recuperação de desastres, raramente acessados.minutos a horas3 ou mais
S3 Glacier Deep ArchiveGuardar por anos, por regra ou lei. É a mais barata.até 12 horas3 ou mais

Fonte: AWS, Amazon S3 storage classes, consultado em 04/11/2026.

E uma regra de ciclo de vida (lifecycle) muda os objetos de classe sozinha com o tempo: por exemplo, para o Standard-IA depois de 30 dias e para o Deep Archive depois de um ano.

Na Ingresso Candango: as fotos e os PDFs (pedido 2) ficam no S3 Standard. Os ingressos antigos (pedido 4) vão para o Glacier Deep Archive, com uma regra de ciclo de vida.

C3

O disco da máquina: EBS e armazenamento de instância

O Amazon EBS (Elastic Block Store) é o disco da instância do EC2. Ele continua existindo mesmo se a máquina for desligada.

  • Fica numa zona de disponibilidade e liga em máquinas da mesma zona. Os dados são copiados entre vários servidores dentro dela.
  • Tem tipos SSD (para bancos e sistemas) e HDD (para muita leitura em sequência, mais barato).
  • Snapshots são cópias de segurança do disco num momento, que você restaura quando quiser, até em outra zona ou região.

Já o armazenamento de instância (instance store) é um disco físico preso ao servidor onde a máquina roda. É muito rápido, mas temporário: os dados se perdem quando a máquina é parada ou encerrada.

Fonte: AWS, What is Amazon EBS?, consultado em 04/11/2026.

Na Ingresso Candango: o sistema do site (pedido 1) fica no EBS. Os arquivos temporários (pedido 5) podem ir para o armazenamento de instância.

D1 · demonstração

Criando um bucket e enviando um arquivo

No vídeo eu faço junto com você. Faça no seu Learner Lab, um passo de cada vez, e apague tudo no fim.

Faça assim:
  1. Abra o Learner Lab, clique em Start Lab e, com a bolinha verde, clique em AWS.
  2. Abra o S3 pela busca e clique em Create bucket.
  3. Dê um nome único, só com letras minúsculas, números e hífens, como candango-fotos-seunome-2026.
  4. Deixe marcado Block all Public Access (bloquear todo o acesso público). É a lição da aula 4.
  5. Clique em Create bucket e abra o bucket criado.
  6. Clique em Upload, escolha uma imagem do seu computador e envie.
  7. Abra o objeto e veja a Storage class (classe) e o endereço dele.
Teste:
  1. Clique no Object URL (o endereço do objeto). Abriu? Não: o bucket está fechado para o público, como deve ser.
  2. Para apagar: selecione o objeto e apague; depois, selecione o bucket vazio e apague. Por fim, End Lab.

Nunca envie dados pessoais para o laboratório, nem desmarque o bloqueio de acesso público. As telas do console mudam de vez em quando: achou um nome diferente, procure a mesma ideia.

P1 · pegadinha de prova

A classe mais barata que ainda atende

A questão pede "a opção mais barata". A resposta não é sempre o Deep Archive: é a mais barata que ainda atende ao tempo de acesso pedido.

Faça estas perguntas, nesta ordem:
  1. Usa o tempo todo? S3 Standard.
  2. Não sabe quanto vai usar? S3 Intelligent-Tiering.
  3. Usa pouco, mas precisa abrir na hora? Standard-IA. Se dá para recriar o dado, One Zone-IA, mais barato.
  4. É arquivo morto que precisa abrir na hora? Glacier Instant Retrieval.
  5. Pode esperar minutos ou horas? Glacier Flexible Retrieval.
  6. Pode esperar até 12 horas, e é para guardar por anos? Glacier Deep Archive.

E as outras pegadinhas do módulo: o EBS fica numa zona só; o armazenamento de instância perde os dados quando a máquina para; e "várias máquinas Linux na mesma pasta" é EFS, não EBS.

T1

Qual armazenamento?

Agora é com você:

  1. O disco com o sistema operacional de uma instância do EC2.
  2. As imagens de um site, abertas por endereço pela internet.
  3. Uma pasta que dez máquinas Linux leem e gravam ao mesmo tempo.
  4. Um cache temporário, rapidíssimo, que pode sumir quando a máquina para.
  5. Guardar os backups do banco de dados com durabilidade altíssima.
T2

Qual classe do S3?

Agora é com você:

  1. As fotos do show de hoje, abertas a toda hora.
  2. Os ingressos antigos, guardados por cinco anos, que quase ninguém vai abrir.
  3. Arquivos novos, e ninguém sabe ainda se vão ser muito ou pouco usados.
  4. Miniaturas das fotos, pouco usadas, que dá para gerar de novo se sumirem.
  5. Contratos assinados, abertos poucas vezes por ano, mas que precisam abrir na hora.
  6. O backup completo do mês, que só se abre em caso de desastre, e pode esperar algumas horas.
T3

Qual serviço?

Agora é com você:

  1. O servidor do escritório precisa gravar os backups direto no S3, como se fosse um disco local.
  2. Levar para a nuvem as pastas compartilhadas do Windows da empresa.
  3. Mover os objetos para uma classe mais barata, sozinho, depois de 90 dias.
  4. Programar num lugar só os backups do EBS, do RDS e do EFS.
